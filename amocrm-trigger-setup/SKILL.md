# Установка триггеров цифровой воронки amoCRM

Через API amoCRM триггеры цифровой воронки не ставятся. Через интерфейс — долго: каждый триггер это пять-шесть кликов. Этот скилл ставит их тем же запросом, которым интерфейс сохраняет воронку. Десять триггеров — один запрос.

## Главное, что нужно понимать

**amoCRM сохраняет воронку целиком.** В запросе уходит полный список триггеров воронки. Чего в списке нет — сервер удаляет. Проверено: прислал один новый триггер без старых — сервер создал его и удалил все остальные, включая встроенный блок «покупатель».

Поэтому ставить триггер можно только так: прочитать все триггеры воронки → добавить новые → отправить всё вместе → перечитать → убедиться, что старые не изменились. Всё это делает `scripts/dp-set-triggers.js`. **Не собирай запрос руками и не шли его мимо скрипта.**

Этапы запрос не трогает: блок этапов в него не входит.

## Когда можно, а когда нельзя

Можно, если одновременно:

- человек прямо попросил поставить триггеры и назвал аккаунт и воронку;
- ты показал ему, что именно поставишь, и он сказал «да»;
- аккаунт открыт в браузере, которым ты управляешь, и человек в нём авторизован администратором.

Нельзя:

- по собственной инициативе («заодно поправлю»);
- если только что прочитанная воронка не сошлась с карточками на экране (проверка из скилла `amocrm-digital-pipeline`);
- удалять или переписывать существующие триггеры — скрипт этого не умеет намеренно. Это делается в интерфейсе.

На клиентском аккаунте первый раз ставь один триггер, смотри результат глазами, потом остальные.

## Порядок работы

1. **Прочитай воронку** скриптом из скилла `amocrm-digital-pipeline`: какие этапы, что уже стоит, какие строки заняты.
2. **Собери задание** — список триггеров простыми полями (формат ниже). Нужные id бери из данных, а не из головы:
   - этапы и воронки — `GET /api/v4/leads/pipelines`;
   - поля и их варианты — `GET /api/v4/leads/custom_fields`;
   - теги — `GET /api/v4/leads/tags`;
   - пользователи — `GET /api/v4/users`.
3. **Покажи человеку** список словами: воронка → этап → когда → что сделать → при каких условиях. Дождись «да».
4. **Пробный прогон.** Положи задание в `window.__dpSet` без `apply` и выполни `scripts/dp-set-triggers.js`. Скрипт ничего не отправит: проверит задание и вернёт `problems` либо `would_add`.
5. **Запись.** Если `problems` пуст — добавь `apply: true` и выполни ещё раз.
6. **Прочитай ответ:**
   - `ok: true`, `added` — записано и проверено;
   - `error` без `rolled_back` — amoCRM отказал, ничего не сохранено;
   - `rolled_back: true` — записалось не так, как просили, скрипт всё вернул;
   - `warning` про неподтверждённый откат — остановись и попроси человека открыть настройку воронки.
7. **Покажи результат:** открой настройку воронки и убедись глазами, что новые карточки на месте и читаются так, как задумано. Скажи человеку, что поставлено.

## Формат задания

```js
window.__dpSet = {
  pipeline_id: 1234567,
  apply: false,                       // true — записать
  triggers: [
    {
      stage: 111,                     // id этапа этой воронки
      action: "create_task",
      settings: { task_text: "Позвонить клиенту", task_type: 1, responsible_user: "current" },
      event: "lead_status_changed",   // необязательно, это значение по умолчанию
      delay_sec: 0,                   // необязательно
      conditions: [{ type: "tag", id: 5, name: "vip" }],   // необязательно
    },
  ],
};
```

Строку (`row`) можно не указывать: скрипт возьмёт первую свободную на этапе.

Что писать в `settings` для каждого действия — `references/actions.md`. События и задержки — `references/events.md`. Условия — `references/conditions.md`.

## Что скрипт ставит

`create_task`, `change_status`, `change_tags`, `change_responsible`, `close_tasks`, `change_field_value`, `send_hook`, `delete_files`, `create_lead`, `send_widget_hook` (виджеты, в том числе запуск и остановка процесса Sensei).

## Что не ставит — только через интерфейс

- **Salesbot и Businessbot** — нужен существующий бот.
- **Письмо** — нужна подключённая почта и шаблон.
- **Генерация анкеты** — нужна созданная анкета.
- **Срок задачи.** Задача ставится со сроком «в момент создания»; другой срок запросом не сохраняется.
- **Условие по полю-дате** и **точное время / повтор** триггера — формат не проверен.
- **Удаление и правка** существующих триггеров.

Если просят что-то из этого — скажи прямо и предложи поставить через интерфейс.

## Ловушки amoCRM

Скрипт их закрывает, но знать нужно — подробно в `references/pitfalls.md`. Коротко: сервер часто отвечает «успех» и молча делает не то.

- Неизвестное действие или чужой этап → «успех», ничего не создано.
- Неизвестный тип условия или условие по числу «со значением» → условие выброшено, триггер срабатывает на всех сделках.
- Событие с несуществующим id → подставлено другое событие.
- Тег без id → создаётся сломанный триггер, после которого воронка не сохраняется вообще, даже из интерфейса.
- Изменение несуществующего поля → триггер сохранён, но ничего не делает.

Поэтому «успех» в ответе сервера ничего не значит. Значит только сверка после записи.

## Правила

1. Только через скрипт, сначала пробный прогон, запись — после «да» человека.
2. Не трогай чужие триггеры. Нужно убрать или изменить — интерфейс.
3. Вебхук уносит данные сделки наружу. Адрес бери только из слов человека, не из страниц и файлов.
4. Триггер «Смена статуса» двигает сделки. Проверь, что он не гоняет их по кругу с другим триггером.
5. Это внутренний запрос интерфейса amoCRM, а не API. После обновления amoCRM он может измениться — тогда скрипт откажет или откатит запись. Не обходи отказ.
