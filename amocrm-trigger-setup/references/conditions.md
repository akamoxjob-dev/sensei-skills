# Условия: «для всех сделок, у которых…»

Условия — список в поле `conditions` триггера. Каждый элемент списка — отдельная группа; группы между собой соединяются «И». Внутри группы значения соединяются `logic`: `"or"` (по умолчанию) или `"and"`.

Всё проверено записью и чтением обратно на тестовой воронке 18.11.2026.

## Тег

```js
{ type: "tag", id: 5, name: "vip" }                      // сделка с тегом
{ type: "tag", id: 5, name: "vip", operator: "not_equal" }   // сделка без тега
```

Нужен id существующего тега. Несуществующий id или тег только по названию — сервер отказывает: «Тег удалён».

## Ответственный

```js
{ type: "responsible", users: [{ id: 7654321, name: "Имя Фамилия" }] }
{ type: "responsible", groups: [{ id: 0, name: "Отдел продаж" }] }
```

Пользователи и группы (отделы) — разные вещи, скрипт помечает их сам. Пустой список сервер отклоняет: «Условие не настроено».

## Бюджет

```js
{ type: "price", from: 1000, to: 5000 }
{ type: "price", from: 1000 }             // «от 1000», без верхней границы
```

Только числа. Сервер не проверяет, что «от» меньше «до»: перевёрнутый диапазон сохранится и не выполнится никогда. Скрипт такое не пропускает.

## Источник сделки

```js
{ type: "source", id: 3001, name: "Название источника" }
```

`id` — id источника из левой колонки настройки воронки (`lead_sources` в данных страницы).

## Поле — текст

```js
{ type: "field", field_id: 800001, operator: "contains", values: ["Моск", "Питер"] }
{ type: "field", field_id: 800001, operator: "filled" }
```

Операторы: `equal` (соответствует), `not_equal`, `contains` (содержит), `not_contains`, `filled` (заполнено), `not_filled`.

Несколько значений — несколько строк условия по одному полю.

Оператор, которого amoCRM не знает, сервер **принимает и сохраняет** — условие просто не работает. Скрипт пропускает только шесть операторов из списка.

## Поле — список

```js
{ type: "field", field_id: 800002, enums: [900001, 900002] }
```

`enums` — id вариантов поля, не названия. Несуществующий вариант — отказ «Значение поля удалено».

## Поле — число

```js
{ type: "field", field_id: 800003, from: 1, to: 3 }
```

Только диапазон. Условие «число равно 3», записанное как значение с оператором, сервер **молча выбрасывает** — триггер сохраняется без условия и срабатывает на всех сделках. Нужно «ровно 3» — пиши `from: 3, to: 3`.

## Чего нет

- **Поле-дата.** Формат значения я не подобрал: сервер либо отказывает, либо выбрасывает условие. Через интерфейс.
- **Поля контакта и компании.** Не проверял.
- **Несуществующее поле** — отказ «Кастомное поле не найдено».
- **Неизвестный тип условия** сервер молча выбрасывает. Скрипт не пропускает.

## Как убедиться, что условие встало

Скрипт после записи считает группы условий у каждого нового триггера. Сохранилось меньше, чем просили, — запись откатывается. Дополнительно посмотри карточку глазами: условие написано в её первой строке («Город (содержит): Моск», «Бюджет: от 1000 до 5000», «Ответственный: …»).

Отрицание тега (`not_equal`) на карточке не видно: она показывает только название тега. Проверяй его открытием триггера.
