# Действия: что писать в `settings`

Всё ниже проверено записью на тестовой воронке 18.11.2026. Где не проверено — так и написано.

## `create_task` — Создать задачу

```js
{ task_text: "Позвонить клиенту", task_type: 1, responsible_user: "current" }
```

- `task_type` — id типа задачи: 1 «Связаться», 2 «Встреча», свои типы — их id из аккаунта. Несуществующий тип amoCRM примет, карточка будет без названия типа.
- `responsible_user` — `"current"` (текущий ответственный), `"creator"` (создатель сделки) или id пользователя. Несуществующего пользователя сервер отклоняет.
- `task_text` можно оставить пустым.
- **Срок задачи запросом не ставится:** сохраняется «в момент создания». Нужен другой срок — интерфейс.

## `change_status` — Смена статуса

```js
{ pipe_id: 1234567, status_id: 222 }     // и обязательно delay_sec: 300 или больше
```

- Без задержки сервер отказывает: «настроить мгновенное исполнение невозможно, чтобы избежать зацикливания». Минимум 300 секунд.
- Этап должен принадлежать воронке `pipe_id`, иначе отказ.

## `change_tags` — Редактировать теги

```js
{ action: "link", tags: [{ id: 5, name: "vip" }] }      // link — добавить, unlink — убрать
```

- Тег обязан существовать, нужен его **id**. Тег только по названию создаёт сломанный триггер без тегов — см. `pitfalls.md`.

## `change_responsible` — Сменить ответственного

```js
{ responsible_id: 7654321, user_name: "Имя Фамилия" }
```

Несуществующего пользователя сервер отклоняет.

## `close_tasks` — Завершить задачи

```js
{ task_type: "all", task_close_time: "all", tasks_text: "" }
```

`task_close_time`: `all`, `expired` (просроченные), `today`, `tomorrow`. Проверено только `all`.

## `change_field_value` — Изменить поле

```js
{ fields: [{ field_id: 800001, value: "123" }] }
```

- Для списка `value` — id варианта. Сохраняется, но карточка показывает только название поля; что запишется в сделку при срабатывании, я не проверял — проверь на тестовой сделке.
- **Несуществующее поле сервер принимает**: триггер сохраняется и молча ничего не делает. Скрипт такое не пропускает.

## `send_hook` — Отправить webhook

```js
{ url: "https://example.com/hook" }
```

Адрес проверяется сервером: не адрес — отказ.

## `delete_files` — Удалить файлы

`settings` можно не указывать: скрипт подставит «все файлы». Действие необратимое для файлов в сделках — ставь только по прямой просьбе.

## `create_lead` — Создать сделку

```js
{ pipe_id: 1234567, status_id: 222, responsible_user: "current", contacts: 1, company: 0, price: 0, tags: 0, talks: 0 }
```

Флаги — что переносить в новую сделку (1 / 0). Перенос отдельных полей — ключи `field_<id>: 1`.

## `send_widget_hook` — действие виджета (Sensei)

```js
{
  widget_id: 555555,                 // id виджета в этом аккаунте
  widget_code: "amo_sensei",
  name: "Sensei: Запустить Название процесса",   // подпись на карточке триггера
  widget: { settings: { account_id: "12345678", process_id: "4321", process_name: "Название процесса", process_direction: "", close_tasks: "" } },
}
```

- `widget_id` возьми из уже стоящего триггера этого виджета (поле `widget_id` в данных чтения). Если такого триггера ещё нет — запросом `GET /api/v4/widgets/<код виджета>` (поле `id`); то же число на странице аккаунта лежит в `AMOCRM.widgets.list.<код виджета>.id`. Код виджета Sensei — `amo_sensei`.
- `process_direction`: `""` — запустить, `"stop"` — остановить. Остановку запросом я не проверял.
- `process_id` и `process_name` бери из MCP-сервера Sensei: `process_name` — название процесса, как оно есть.
- **`name` обязателен.** Без него триггер работает, но карточка в интерфейсе пустая.

## Не ставится запросом

`send_chat_message` (Salesbot), `business_bot`, `send_email`, `create_and_fill_form` — нужны бот, почта с шаблоном или анкета. Несуществующего бота сервер отклоняет: «один или несколько ботов были удалены».
